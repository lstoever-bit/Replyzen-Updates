# Native 2.0 update for the existing ReplyZen installation

The user explicitly requested delivery through **Nach Updates suchen**, rather than
a separately downloaded diagnostic or preview application.

This target retains bundle ID `com.lstoever.replyzen`, the existing keychain service,
preferences, login-item behavior, the update menu, and the complete original
`UpdateManager.swift`. It changes the mail transport to the native Outlook core.
The previously removed automatic updater/menu are restored in the assembled bundle.

The installed 1.75 updater already verifies the SHA-256, validates the bundle ID,
and signs downloaded builds using the existing **Replyzen Local Signing** identity
on the user's Mac. This release uses that established path without removing or
relaxing its checks. No certificate, key or user secret is downloaded by CI or
committed. The artifact is **not a notarized standalone installer**. Do not describe
it as one, offer it as a replacement for a first-time installation, or promise that
CI tested the user's local certificate or Automation permission.

The separate `sign-release.sh` Developer ID/notarization gates continue to apply to
standalone distribution. They are not used to replace the installed local updater.

Run `prepare-update.py` to assemble `.native-build`, then its existing `Build-CI.sh`.
`verify-update.py` verifies the exact archive, native script, restored update menu,
preserved settings and unchanged updater. `UpdaterCompatibilityTests.swift` executes
the real updater's private manifest decoding, URL resolution, checksum and bundle
lookup against the built package, without installing or altering a user's keychain.
CI publishes package and feed together only on main after successful validation.

Version: **2.0.0 / build 200**. The update requires classic Outlook for Mac with
AppleScript support. macOS may ask for Automation permission to control Outlook.
No automatic sending is implemented. Complete live testing against the user's
signed-in Outlook mailbox remains outstanding and is stated in the update notes.
The former GUI source remains under `source-current` as the preserved baseline;
the assembled 2.0 source is reproducibly generated by the rewrite/release scripts.
